# 0.49.0

信頼性の改善。**要約の生成中にアプリが異常終了しても、完了した文字起こしを
失わない** ようになりました (エンジン kilde-cli-swift#153 «退避書き出し
(TranscriptStash)» の取り込みと、GUI 要約経路への適用 — kilde#629)。

この改善は «録画後の要約 (議事録)» を有効にしているときだけ関係します。
要約は Apple Intelligence を使う機能で、**Apple Intelligence が利用できる
macOS 26 以降** の環境で選択したときだけ実行されます (非対応環境では要約は
スキップされ、文字起こしだけが保存されます — この挙動は従来どおりです)。

## この版の内容

- 要約の生成 (オンデバイス LLM の map-reduce) の道中でアプリがクラッシュ・
  強制終了・電源断しても、完走済みの文字起こしを隠し退避ファイルとして残す
  ようにしました。次に同じ録画の要約を実行したときに、確定ファイルの
  連番候補へ自動で回復します
- 中止したときの挙動は従来どおりです — 退避も確定ファイルも残りません
  («中止時は確定ファイルを書かない» 契約 — kilde-cli-swift 側 DESIGN.md §4)
- 要約の生成に失敗した場合は従来どおり、要約なしの文字起こしを保存して理由を
  案内します (退避は確定の保存後に削除)
- 既存の文字起こしファイルを上書きすることはありません (確定ファイルの
  上書き禁止 — kilde-cli-swift#36 の契約は退避によっても変わりません)
- 録画・文字起こし・要約の生成方法自体は変わりません

## GUI

- 文字起こし完了後の後半処理を `TranscriptionCoordinator.summarizeAndWrite`
  に抜き出し、エンジンの `TranscriptStash` (退避の書き出し・削除・孤児回復) を
  採用しました。GUI の要約経路はエンジンの `TranscriptionRun` を経由しないため、
  pin 更新だけでは窓が塞がらない (PR #158 で指摘された点) のを、この PR で
  塞ぎます
- セルフテスト `KILDE_GUI_SELFTEST_TRANSCRIPT_STASH=1` を追加しました
  (要約の道中で退避が存在すること / 中止時に退避も確定も残らないこと /
  成功・要約失敗・要約スキップでの退避の後始末 / 孤児退避の回復 /
  既存確定の上書き禁止 / 退避の書き出しに失敗した場合の fail loud)。
  検証結果: 29 件全 ok、failures=0
