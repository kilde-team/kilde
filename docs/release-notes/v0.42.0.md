# 0.42.0

## 要約の生成に失敗しても、文字起こしは残るように

- **要約 (議事録) の生成に失敗したときも、文字起こしのファイルは保存されるようになりました** (issue #575 — エンジン kilde-cli-swift#151 / kilde-cli-swift PR #152、GUI は issue #577 / PR #585)。以前の版では «文字起こし + 要約» の両方を有効にして録画したとき、要約が失敗すると (内容がモデルの文脈長を超えた、ガードレールに触れた等) 文字起こしのファイルも書かれませんでした。文字起こしはすでに完走しているので、要約の成否に関わらず保存します
- **要約は «録画後に要約» を有効にした録画が対象で、Apple Intelligence のオンデバイス処理 (macOS 26 以降) で生成します** — Apple Intelligence が使えない環境では要約は無効です (ツールチップに理由が表示されます)
- 失敗したことは従来の案内経路 («要約は生成できませんでした (理由)» — 完了通知とライブラリの note) で伝えます。**文字起こしの処理を中止したときは従来どおり文字起こしのファイルを書かず、録画のファイルは残ります** — «中止時は出力ファイルを書かない» 契約 (エンジンの DESIGN.md §4 «生成の途中の失敗» — kilde-cli-swift#151 で追記) は変わりません

## ライブラリの «質問する» «翻訳» «ライブラリに質問» に話者が渡るように

- **ライブラリの録画索引に話者ラベルを保持し、«質問する» «翻訳» «ライブラリに質問» の結果に話者名が現れるようになりました** (issue #566)。«誰が言ったか» を問う質問の精度が上がり、翻訳の各行が原文のどの行に当たるか (時刻 + 話者) も読める形になります
- **話者名は、マイクとシステム音声を «別トラック» で録った録画の文字起こしに表示されます** (話者ラベルは 2 トラック録音に付きます — マイク側が «自分»、システム音声側が «相手»。1 トラックに混合した録画ではラベルが付かず、従来どおりの表示です)。話者ラベルは文字起こしのサイドカー (md / json / srt / vtt / txt) から復元し、従来の録画は後方互換でそのままです
- なお文字起こしの表示行と書き出し (txt / srt / vtt) は今回スコープ外で、話者は入りません (PR #581 のコメントに記載)

## ライブラリまわりの修正

- **«質問する» の入力欄でスペースが入力できない問題を直しました** (issue #573 / PR #584)。単一録画版の «質問する» だけが入力ごとに前後の空白を削っていたのが原因です (横断版 «ライブラリに質問» は 0.40.0 のレビューで直済み)。空白は入力中そのまま残り、«答えを得る» を押したときにだけ正規化します
- **音量スライダーが «名前を変更» «ゴミ箱に入れる» に重なって表示される問題を直しました** (issue #574 / PR #586)。macOS 26 の AVPlayerView は浮動操作系を領域の端に描くため、右上 overlay のボタンと重なっていました。2 つのボタンをプレイヤー下の専用行へ移動し、文字起こしの有無に関係なく表示します (ゴミ箱に入れるはサイドカーの無い録画の唯一の整理導線のため)
- **英語など日本語以外で使ったときの表示を直しました** (issue #571 / PR #582、issue #572 / PR #583)。要約チェックの説明・録音告知のコピーのボタン・«Recording Library» ボタン・ライブラリの検索欄・件数表示 («1 recording · 1 transcript» の複数形つき)・空のときの案内など、翻訳が登録されていなかった 50 キーを en / es / ko / zh-Hans に追加しました。日本語の表示は変わりません

## エンジン (kilde-cli-swift) の更新

- 録画エンジン (KildeCore) を **v0.27.0** に更新 (issue #151 / PR #152 — `TranscriptionRun` の要約失敗の捕捉と `RunResult.completed` の `summaryFailure`。DESIGN.md §4・§6 に契約を追記)。録画の挙動 (収録・文字起こしの実行) に変更はありません
