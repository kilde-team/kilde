# 機密性の高い会議を、クラウドに上げずに議事録にする

*— kilde という、手元で完結する Mac の録音・文字起こしツールの紹介 —*

**この記事について** (リポジトリ内の注記です。note に転載するときは削除してください):
issue #158 の利用者向け記事の下書きです。執筆時点 (2026-09-28) の kilde の挙動に基づいています。

---

「今日の打ち合わせ、議事録取っといて」——この一言、上手にこなせる人は本当に少ないと
思います。私は苦手でした。

最近は AI が議事録を作ってくれるサービスがたくさんあります。ただ、それらの多くには
**会議にボットが参加する**か、**音声をクラウドに送る**という前提があります。
自分一人で使う分には便利なのですが、こういう場面でためらいます:

- 顧客の個人情報や未公開の数字が出る打ち合わせに、外部サービスのボットを招きたくない
- 「この会議、録音して大丈夫?」と毎回説明するのがしんどい
- 会議ツールがボットに対応していなかったり、参加を拒否する設定だったりする

結局「録音はせず、メモを取りながら頑張る」を繰り返して、会議後に自分のメモと記憶を
突き合わせて議事録を書く。これ、時間も精神も持っていきます。

## 「手元で完結する」という選択肢

[kilde](https://kilde.site/) は、macOS の画面と音声を録る無料のツールです。
特徴をひとことで言うと、**録音と、設定をオンにした文字起こし・要約を
Mac の中で完結できる**こと (文字起こしは macOS 26 以降、要約は
Apple Intelligence 対応 Mac が必要です)。会議にボットは入らないし、
音声がどこかにアップロードされることもありません。

使い方は、普通の会議と同じままです。ただし最初に大事なことをひとつ:
**録画の前には、参加者のみなさんに録音することを伝えて同意を得てください**。
ボットが入らないからといって、そのひと手間が要らなくなるわけではありません
(伝える用の告知文をワンクリックでコピーできる機能も入っています)。

1. Mac App Store (無料) から kilde を入れて、メニューバーにアイコンを表示させる
2. 初回の録画時に、画面収録とマイクの許可を求められたら許可する (アプリが案内してくれます)
3. 会議が始まったら、メニューバーのアイコンから会議のウィンドウを選んで録画開始
4. 会議が終わったら停止。**相手の声と自分の声が 1 つのファイルに録れています**
5. 「録画後に文字起こし」をオンにしておくと、停止した瞬間から文字起こしが走る

コマンドライン派の方は、Homebrew で `kilde` コマンドを入れて
`kilde doctor` (許可の案内) → `kilde rec --preset meeting meeting.mov` でも同じことができます。

文字起こしは macOS 26 以降の端末なら、macOS 組み込みの音声認識で
**手元の Mac の中だけで**行われます。生成されるのはタイムスタンプ付きの議事録で、
Markdown・SRT・字幕 (WebVTT)・テキスト・JSON の好きな形で取り出せます。

## 音がきれいに残るのは、話者を分けられるから

kilde が会議録音として使いやすいのは、**相手の声 (Mac が再生している音) と
自分の声 (マイク) を両方**録れること、そして必要なら**トラックを分けられる**ことです。

分けて録ると、文字起こしもトラックごとに行えるので、「相手が話したこと」と
「自分が話したこと」が混ざらずに議事録になります。後から読み返すとき、
「自分が約束したこと」だけを抜き出して確認できるのは、地味にありがたいです。

もうひとつ細かいけれど大事な点: 録るウィンドウを会議の 1 ウィンドウに絞ると、
**音もそのアプリに絞られる**ので、メッセージの着信音が議事録に入りません。
録画中に通知が来ても、議事録は汚れません。

## 「本当に送信されてないの?」について

ここが一番の関心事だと思うので、正直に書きます。

- 録画・録音・文字起こし・要約の結果は、すべて手元のディスクに書かれます。
  kilde のサーバーは存在しません
- メニューバーアプリは、動作改善のため Firebase Analytics に利用統計を送ります。
  起動回数や OS バージョン、録音の長さの区分 («1分未満 / 1〜5分 / 5〜15分 / …» など)
  が対象です。開発者が見られるのは集計された統計で、録音の内容やファイル名、
  保存先などの設定は送りません
- アプリがクラッシュした場合は、次の起動時に Firebase Crashlytics が個別の
  クラッシュレポートを送ります。落ちた処理や端末の状態などが含まれますが、
  録音の内容やファイル名、保存先などの設定は含まれません
- 直接配布版のアプリは、更新確認のため Sparkle が GitHub の更新情報を取得します。
  この通信では IP アドレスやアプリのバージョンなどが GitHub に伝わります。
  Mac App Store 版の更新は App Store 経由です
- 文字起こし用の言語モデルが端末にない場合は、アプリ版・コマンドライン版とも
  Apple からモデルをダウンロードします。この通信で IP アドレスは Apple に
  伝わりますが、録音や書き起こしテキストは送られません
- コマンドラインの `kilde` は Firebase Analytics・Crashlytics や Sparkle を使いません。
  上記のモデル取得を除いて外部通信は行いません
- この辺りは[プライバシーポリシー](https://kilde.site/ja/privacy/)に
  具体的に書いてあるので、導入前に読めます

「クラウドに上げない」を売りにするなら、この部分の説明に逃げがないことが条件だと
思うので、くどいほど書いてあります。

## どんな人に向いているか

- 顧客対応や採用面接など、**ボットを招けない会議**の議事録が必要な人
- 音声を外部サービスに送ることに会社から許可が出ない人
- 会議の内容を、後で全文検索したい人
- 逆に、クラウド同期やチーム共有が主目的なら、ほかのサービスの方が適していると思います
  (kilde はあくまで「手元で完結」が主役の道具です)

kilde は無料で、[公式サイト](https://kilde.site/ja/)と
[Mac App Store](https://apps.apple.com/app/id6812783176) から入れます
(メニューバーアプリとドキュメントはオープンソース / MIT で公開されています)。
macOS 14 以降の Apple Silicon の Mac が対象で、文字起こしは macOS 26 以降で使えます。

「議事録取っといて」に怯えなくなるだけで、会議の前が少し軽くなると思います。
