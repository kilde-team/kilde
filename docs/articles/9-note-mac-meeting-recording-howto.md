# 会議を録音したら、自分の声しか録れていなかった — Mac で相手の声も残す方法

*— kilde という、Mac の録音・文字起こしツールの紹介 —*

**この記事について** (リポジトリ内の注記です。note に転載するときは削除してください):
issue #312 の利用者向け記事の下書きです。執筆時点 (2026-10-06) の kilde の挙動に基づいています。
公開済みの note 記事 «機密性の高い会議を、クラウドに上げずに議事録にする»
(`3-note-private-meeting-minutes.md`) とは訴求を分けています:
あちらは «クラウドに上げない» こと自体が主題、こちらは
«QuickTime では相手の声が録れない» という気づきから入る how-to が主題です。

---

先日、打ち合わせを録音したファイルを見直していたら、変なことに気づきました。
**再生しても、自分の声しか入っていない**んです。

「相手の声が入っていないと、議事録として意味が無い…」
⇧⌘5 (Screenshot ユーティリティ) で録っていたので、てっきり会議の音声ごと
録れていると思い込んでいました。調べてみるとこれは仕様で、
**macOS の標準機能で画面収録をすると、選べる音声はマイクだけ**です。
QuickTime Player の画面収録も同じ。Mac がスピーカーから再生している音
(システム音声) をファイルに落とす経路が、標準機能には用意されていません。

オンライン会議の「相手の声」は、ヘッドホンやスピーカーから再生される
Mac 内部の音なので、マイクにはほぼ入りません。
つまり標準機能での会議録音は、構造的に**自分の声しか残らない**んです。

## 解決策は 2 つ

「Mac が再生している音」を録るには、大きく 2 つのやり方があります。

**1. 仮想オーディオドライバを入れる**
BlackHole (無料) のようなドライバを入れて、システム音を「マイクの一種」に
見せる方法。無料で実現できるのですが、ドライバのインストール、
入出力の経路設定、会議ごとの入力切替…と、最初のハードルと毎回の手間があります。

**2. ScreenCaptureKit ベースの録画ツールを使う**
macOS の画面収録フレームワークである ScreenCaptureKit は、
システム音声を直接録れます。ドライバの追加インストールは不要です。

私は仕事で macOS アプリを作っているので 2 の道で自作しました。
それが [kilde](https://kilde.site/) です。無料で、
[Mac App Store](https://apps.apple.com/app/id6812783176) から入れます。

## kilde での会議録音

使い方は単純で、メニューバーのアイコンから**会議のウィンドウを選んで**
録画開始するだけです。初回の録画時には「画面収録」と「マイク」の
2 つの許可を求められます (相手の声の収録には画面収録の許可、自分の声には
マイクの許可が要ります。アプリが案内してくれます)。

ここでウィンドウを指定するのがポイントで、kilde では
**録る対象を 1 つのアプリのウィンドウに絞ると、音もそのアプリに絞られます**。
会議の音は入りつつ、録画中に届いたメッセージの通知音は入りません。
「会議を録っていたら通知音が入っていた」あるあるも、これで防げます。

録れる音は:

- **相手の声** (Mac が再生しているシステム音声)
- **自分の声** (マイク)

の両方で、1 つのファイルにミックスするか、**トラックを分けて**保存するかを
選べます。分けておくと、後述の文字起こしで «相手 / 自分» のラベル付きの
議事録が作れます。「自分が何を約束したか」だけを後で見返せるのは、地味に助かります。

「録画後に文字起こし」をオンにしておくと、録画の停止と同時に
文字起こしが走ります (macOS 26 以降。Mac の中だけで処理されます)。
出力は Markdown・SRT・字幕 (WebVTT)・テキスト・JSON から選べるので、
議事録にも、動画の字幕にも使えます
(要約は Apple Intelligence 対応 Mac で使えます)。

コマンドライン派の方には Homebrew で `kilde` コマンドも用意してあります。

## 録るときのひとこと (これが一番大事)

ツールの話に寄りきりましたが、最初に書くべきことを書きます:
**録画の前には、参加者のみなさんに録音することを伝えて同意を得てください**。
相手の声が録れるようになって便利になった分、このひと手間は確実に必要です。

kilde には「会議を録音します」と伝えるための告知文を
ワンクリックでコピーできる機能が入っているので、
毎回文章を考える手間だけは省けます。

## 「録った音はどこに行くの?」

手元で完結するツールなので、録音・文字起こしの結果は
**すべて Mac 内のディスクに書かれます**。kilde のサーバーは存在しません。

- メニューバーアプリは、動作改善のため Firebase Analytics に利用統計を送ります
  (起動回数や利用頻度、アプリと OS のバージョン、端末の種類、IP アドレスから
  推定される大まかな地域、録画の完了回数や長さの区分、使っている版
  — App Store 版か直接配布版か —、文字起こし機能の利用状況など)。
  開発者が見られるのは集計値で、録音の内容やファイル名、保存先などの設定は送りません
- アプリがクラッシュした場合は、Firebase Crashlytics が個別の
  クラッシュレポートを送ります (クラッシュ時のスタックトレース、アプリと
  OS のバージョン、端末の種類や状態、クラッシュの日時、アプリの
  インストールごとに割り振られるランダム ID など。録音の内容や
  ファイル名、保存先などの設定は含まれません)
- 公式サイトから入れた直接配布版は、更新確認のために GitHub 上の更新情報を
  取得します。この通信で IP アドレスやアプリのバージョンが GitHub に伝わります
  (Mac App Store 版の更新は App Store 経由です)
- 文字起こし用の言語モデルが端末に無い場合は、Apple からモデルを
  ダウンロードします (この通信で IP アドレスは Apple に伝わりますが、
  録音や書き起こしテキストは送られません)

この辺りの詳細は[プライバシーポリシー](https://kilde.site/ja/privacy/)に
具体的に書いてあります。導入前に読めますし、公開もしています
(メニューバーアプリとドキュメントはオープンソース / MIT です)。

## どんな場面で効くか

- **QuickTime で会議を録ったら自分の声しか無かった**人 — 今回の私です
- 相手の発言を正確に残したい (見積もりの条件、要件の確認など) 人
- 通知音が混ざった録音を作りたくない人
- 録った音を、手元の Mac だけで文字起こししたい人

kilde は無料で、macOS 14 以降の Apple Silicon の Mac が対象です。
文字起こしは macOS 26 以降で使えます。
[公式サイト](https://kilde.site/ja/)と
[Mac App Store](https://apps.apple.com/app/id6812783176) からどうぞ。

「相手の声も、ちゃんと録れていた」——会議の録音は、そこからが本来の価値です。
