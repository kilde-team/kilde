# App Store 計測: メタデータ変更前後のインプレッションと DL (issue #160)

issue #160 の受け入れ条件「変更前後 4 週間のインプレッションと DL 数を記録した」の
計測台帳。**数値は App Store Connect → 分析 (App Analytics) が正本**で、この
ファイルはそこからエクスポートした値の記録。

## 比較する変更

- **変更内容** (2026-09-26 にこのリポジトリで確定、PR は issue #160 参照):
  全 5 ロケールのサブタイトル・説明・キーワードを文字起こし前面の文面へ更新し、
  他社商標 (Zoom 等の会議サービス名、BlackHole) を除去。アプリ名は不変
- **反映のタイミング**: 0.8.1 のバージョンを作成してメタデータを転記し、
  審査を通って公開された時点 (= 下の「反映日」)。0.6.0 が審査中の間は
  次バージョンを作れないため、反映日は 0.6.0 の承認後に決まる
- **比較期間** (CodeRabbit レビュー指摘で重複を解消 — 反映日は「後」にのみ数える):
  前 = 初公開 (0.3.0、2026-09-16 提出・リジェクトを経て 2026-09-18
  頃に初公開 — 正確な日は下のエクスポートで確認) 〜 **反映前日** /
  後 = 反映日 〜 反映日 + 4 週間

## 計測方法

1. App Store Connect → kilde → 「分析」を開く
2. 指標: **App ストアのインプレッション** / **App プロダクトページビュー** /
   **App 単位 (ダウンロード)**。ディメンションは「ソース」
   (App Store 検索 / App Store ブラウズ / プロダクトページ / App 参照) で絞る
   — #160 の目的が「App Store 内検索からの流入」なので、**検索経由の行を
   最重視**する
3. 期間を設定して CSV エクスポート (画面右上の … メニュー) し、
   週次の行を下の表へ転記する
4. App Analytics API (`analyticsReportRequests`) は初回生成に時間がかかるため
   使わない (asc-submit にも実装が無い)。手動エクスポートで十分。
   2026-09-26 時点ではブラウザセッションが ASC にログインしていないため
   数値の自動取得はできていない — **最初のエクスポートは 0.8.1 のメタデータを
   ASC に転記する際に同じセッションで行う**と手間が一度で済む

## 読み方の注意

- DL は App 単位 (初回ダウンロード)。更新は含まない
- インプレッションは検索結果・おすすめ・プロダクトページで露出した回数の合計。
  「検索経由」の行が #160 の主指標
- 変更と同時期に 0.8.1 の新機能 (文字起こし等) 自体が流入を増やすので、
  メタデータ単独の効果は切り分けられない。変化は「メタデータ + 機能追加の
  合成効果」として報告する
- 短期間の変動 (レビュー掲載・外部発信) に左右されるので、週次トレンドで見る
