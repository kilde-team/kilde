## 計測する指標

ASC 分析の指標を使う (Apple の
[指標定義](https://developer.apple.com/help/app-store-connect-analytics/reference/metrics-definitions))。
コンバージョン率の追加は依頼者指示 2026-09-28:

| 指標 | ASC 分析の指標名 | 定義 |
|---|---|---|
| ユニーク表示 | App ストアの表示 (ユニークデバイス) | App Store で App を表示したユニークデバイス数 (検索結果・おすすめ・プロダクトページ等の合計) |
| うち検索経由 | 同上を「ソース = App Store 検索」で絞る | #160 の主指標 (App Store 内検索からの流入) |
| ユニークページ閲覧 | 製品ページビュー (ユニークデバイス) | プロダクトページを表示したユニークデバイス数 |
| 初回 DL | ダウンロード数 (App 単位) | 初回ダウンロード。更新は含まない |
| 再 DL | 再ダウンロード数 | 同じ Apple ID による再ダウンロード |
| CVR | コンバージョン率 | **ダウンロード数 ÷ ユニークデバイスの表示数**。製品ページ閲覧数を分母にしない (0.8.1 公開前の 90 日集計で「11.1%」と読んだ値はデータ不足で評価に使えない — 2026-09-28 の調査メモ参照) |

旧列の「App ストアのインプレッション (計)」(表示回数の合計) は参考値として
週次表に残してある。

## 計測方法

1. App Store Connect → kilde → 「分析」を開く
2. 指標: 上の表の 6 指標。ディメンションは「ソース」
   (App Store 検索 / App Store ブラウズ / App 参照 / ウェブ参照) と
   「国 / 地域」で絞る — #160 の目的が「App Store 内検索からの流入」なので、
   **検索経由の行を最重視**する
3. 期間を設定して CSV エクスポート (画面右上の … メニュー) し、日次の行を
   週次の表へ集計して転記する。ソース別・国別の表は期間合計で転記する
4. App Analytics API (`analyticsReportRequests`) は初回生成に時間がかかるため
   使わない (asc-submit にも実装が無い)。手動エクスポートで十分

## 読み方の注意

- 初回 DL は App 単位 (初回ダウンロード)。更新は含まない。再 DL は別列
- インプレッションは検索結果・おすすめ・プロダクトページで露出した回数の合計。
  ユニーク表示は同一デバイスを 1 回と数えた値で、CVR の分母はこちら
- **CVR を絶対値で判断しない。** 変更前の件数は DL 数件レベルで、
  1 件の動きで率が大きく動く。見るのは「変更前後の同指標の相対変化」と
  週次トレンド (依頼者指示 2026-09-28: 今すぐ目標値と比較して施策の成否を決めない)
- 変更と同時期に 0.8.1 の新機能 (文字起こし等) 自体が流入を増やすので、
  メタデータ単独の効果は切り分けられない。変化は「メタデータ + 機能追加の
  合成効果」として報告する。変更 2 も同様に「スクショ + 流入施策 (#161) の合成効果」
- 短期間の変動 (レビュー掲載・外部発信) に左右されるので、週次トレンドで見る
